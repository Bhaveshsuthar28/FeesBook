# WhatsApp Principal Bot Local Testing Manual

This document guides you through testing the WhatsApp Principal Bot authentication flow across three layers of isolation: direct unit testing, local webhook simulation, and real live WhatsApp sandbox integration.

---

## Layer 1 — Local Unit Testing
Unit tests run directly in memory against your configured database and Redis cache with zero HTTP/network latency. This provides the fastest feedback loop for verifying the authentication state machine.

### Requirements
- A working dev database (`DATABASE_URL` in `.env`).
- A working dev Redis cache (`CACHE_REDIS_URL` in `.env`).

> [!WARNING]
> This script writes and deletes temporary test rows and session keys. Do not run this script against a production database or production Redis server.

### How to Run
Run the unit test suite from the `Backend` directory:
```bash
node scripts/test-bot-layer1.js
```

### What it Tests
The test script creates isolated credentials (`test-school-1` through `test-school-6`) and mock students, evaluating 13 assertions across these scenarios:
1. **Scenario A (Happy Path)**: Command activation → password entry → successful login → authenticated command execution.
2. **Scenario B (Wrong Password)**: Failed attempts handle recovery and correct password retry.
3. **Scenario C (Lockout)**: Lockout triggers after the 3rd wrong attempt, preventing login attempts.
4. **Scenario D (Silent Fail)**: Non-existent activation commands fail silently without exposing credentials status.
5. **Scenario E (Expiry Simulation)**: Authenticated commands are blocked once Redis TTL expires.
6. **Scenario F (Logout)**: Terminating session blocks future commands.
7. **Scenario G (Parent Bot Multi-Child Query)**: Multiple children matching a single phone number trigger an options selection menu, displaying student details upon response.

## Layer 2 — Simulated Webhook Testing
This layer tests the actual Fastify endpoint parsing, headers, route validation, and dry-run outbound messages by triggering simulated webhook payloads via `curl`.

### Requirements
1. Set `WHATSAPP_DRY_RUN=true` in your `.env` file to log bot replies to the server console instead of sending live Meta API calls.
2. Manually insert or verify test credentials exist for activation command `testlogin123` and password `TestPass@123` (this can be configured via the settings page in your browser).

### How to Run
1. Start your local Fastify server:
   ```bash
   npm run dev
   ```
2. Make the scripts executable:
   ```bash
   chmod +x scripts/test-bot-layer2.sh scripts/test-bot-layer2-flow.sh
   ```
3. Run the automated flow test sequence:
   ```bash
   ./scripts/test-bot-layer2-flow.sh
   ```

### Output Verification
Check your running Fastify server terminal. You should see logs indicating incoming payload parsing and dry-run responses:
```text
📱 [DRY RUN] Reply to 919000000010:
🔐 Enter your bot password to continue.

📱 [DRY RUN] Reply to 919000000010:
✅ Logged in as Principal...

📱 [DRY RUN] Reply to 919000000010:
Available Commands:
- help: Show this guide
- logout: Close active bot session
```

## Layer 3 — Real WhatsApp Sandbox Testing
Follow these steps to route real WhatsApp messages from a mobile phone to your local server using the Meta Sandbox and ngrok.

### Steps
1. Log in to [developers.facebook.com](https://developers.facebook.com) and create a free developer account.
2. Click **Create App**, select **Business** type, and add the **WhatsApp** product.
3. Under **WhatsApp** → **API Setup**:
   - Meta automatically provisions a free test phone number.
   - Under *To*, add your personal phone number as a verified test recipient.
4. Copy the **Temporary access token** and **Phone Number ID**. Save them in `Backend/.env`:
   - `WHATSAPP_ACCESS_TOKEN`
   - `WHATSAPP_PHONE_NUMBER_ID`
   - Also confirm your `WHATSAPP_VERIFY_TOKEN` and `WHATSAPP_API_VERSION` are set.
5. Install and launch `ngrok` to expose your local port:
   ```bash
   ngrok http 5000
   ```
   *(Replace 5000 with your actual local server port `PORT` from `.env`)*
6. Copy the forwarding `HTTPS` URL generated by ngrok.
7. Return to Meta App Dashboard → **WhatsApp** → **Configuration**:
   - **Callback URL**: `<ngrok HTTPS URL>/api/whatsapp/webhook/whatsapp`
   - **Verify Token**: Paste the token matching `WHATSAPP_VERIFY_TOKEN` in your `.env`.
   - Click **Verify and Save**.
8. Under **Webhook fields**, click **Subscribe** on the `messages` line.
9. Change `WHATSAPP_DRY_RUN=false` in `Backend/.env` and restart your local dev server:
   ```bash
   npm run dev
   ```
10. Open WhatsApp on your verified recipient phone.
11. Send your activation command (e.g. `testlogin123`) to the Meta sandbox test number.
12. Enter the bot password when prompted on WhatsApp to authorize the session.
13. Confirm the welcome message and try sending `help` to query or `logout` to terminate.

### Troubleshooting
- **Webhook verification fails**: Check that your `Verify Token` entered on Meta matches `WHATSAPP_VERIFY_TOKEN` in `.env` exactly.
- **No response on phone**: Ensure your phone number is added to the *Verified Recipients* in Meta, `WHATSAPP_DRY_RUN` is set to `false`, and your ngrok tunnel is open.
- **URL expired**: Free ngrok URLs change on every restart. You must update the Callback URL in the Meta Dashboard whenever you restart ngrok.

> [!NOTE]
> Meta sandbox numbers have conversation rate limits and require recipient whitelisting. This is ideal for development testing but requires a production Meta Business Account for release.
